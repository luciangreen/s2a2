  hypothesis tree:
    dropmin: map: each element by the sub-predicate
      dropmin_el: filter (context): keep x when x =\= min_list(l)
  program:
    dropmin([], []).

        dropmin_el(A, C),
        dropmin(B, D).

        A=\=B.

== 4. Genetic algorithm

  The sum of the squares of the even elements is a filter, then a map, then an
  aggregate. No top-down hypothesis splits it, so the GA searches pipelines.
    [1,2,3,4] -> 20
    [2] -> 4
    [1,3] -> 0
    [6,1] -> 36
    [] -> 0
  hypothesis tree:
    sum_sq_evens: genetic algorithm, generation 26: filter((x mod 2) < 1) then map((x*x)) then sum_list
  program:
    sum_sq_evens(A, B) :-
        sum_sq_evens_s1(A, C),
        sum_sq_evens_s2(C, D),
        sum_sq_evens_s3(D, B).
    sum_sq_evens_s1([], []).
    sum_sq_evens_s1([A|B], C) :-
        (   sum_sq_evens_s1_test(A)
        ->  C=[A|D]
        ;   C=D
        ),
        sum_sq_evens_s1(B, D).
    sum_sq_evens_s1_test(A) :-
        A mod 2<1.
    sum_sq_evens_s2([], []).
    sum_sq_evens_s2([A|B], [C|D]) :-
        sum_sq_evens_s2_el(A, C),
        sum_sq_evens_s2(B, D).
    sum_sq_evens_s2_el(A, B) :-
        B is A*A.
    sum_sq_evens_s3(A, B) :-
        sum_list(A, B).
  against the reference on every input of the pool: equal_on(1555)
  ga_pipeline: ok
  seeds 1 to 20: 20 found a pipeline, in 3 to 103 generations, at most 3 genes after shortening
  ga_every_seed: ok

== 5. Active learning with an oracle

  From the single example [[1,3,5],[5,3,2]] -> [[3,5],[5,3]], several programs fit
  (keep x > 2, keep x =\= min, ...). The loop asks the oracle about the input on which
  the candidates disagree most, then checks the survivor on the whole pool.
    query: distinguish([[3]]-[[]],candidates(4))
  rounds: 2; examples used: 2; final check: equal_on(7311)
  program:
    dropmin([], []).
    dropmin([A|B], [C|D]) :-
        dropmin_el(A, C),
        dropmin(B, D).
    dropmin_el([], []).
    dropmin_el([A|B], C) :-
        min_list([A|B], D),
        dropmin_el_sel([A|B], D, C).
    dropmin_el_sel([], _, []).
    dropmin_el_sel([A|B], C, D) :-
        (   dropmin_el_test(A, C)
        ->  D=[A|E]
        ;   D=E
        ),
        dropmin_el_sel(B, C, E).
    dropmin_el_test(A, B) :-
        A=\=B.
  active_dropmin: ok

== 6. From input/output to an algorithm

  With the library aggregate left out, the synthesised program is a plain recursive
  specification. fold.pl turns it into an accumulator program and proves them equal.

--- sum
  specification found from [[1,2,3]-6,[4]-4,[]-0,[2,5]-7] examples:
    sum([],0).
    sum([A|B],C) :- sum(B,D), C is D+A.
  derived by accumulate (lemmas [plus_assoc]):
    sum([],0).
    sum([A|B],C) :- sum_acc(B,C,A).
    sum_acc([],A,B) :- A is 0+B.
    sum_acc([A|B],C,D) :- E is A+D, sum_acc(B,C,E).
  total: yes; specification functional: yes; typed answers: no
  (the specification also adds floats, where the integer axiom does not hold
  exactly, so equality is stated for integer lists, as in results/fold.txt)
  bounded check: equal_on(341)
