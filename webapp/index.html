What S2A2 can do

S2A2 learns how to optimise Prolog programs from a few before-and-after pairs, writes programs from input/output examples, turns specifications into faster algorithms, and proves every result. Each page here runs the real S2A2 code in SWI-Prolog, compiled to WebAssembly, inside this page. Nothing is sent to a server.

Where it sits

S2A2 is the last step of the Manual Neuronets pipeline: it finds the optimisation that turns the original program into the code learned from the network's input and output.

Prolog program→pl2ann network→input recovered from output→code learned from input/output→S2A2: the optimisation, proved

How to use it

Pick a page on the left. Each one opens with a worked example already filled in: press the run button to watch S2A2 work, then edit the input or choose another example. The first run waits for SWI-Prolog to start (a few seconds; it is about 7 MB). A long query can be stopped from the left rail.

Learn an optimisation from two pairs

Each family has two training pairs (an unoptimised program and its optimised form) and one to five test programs S2A2 has never seen. S2A2 finds a derivation for each pair, learns each operator's conditions by sequential covering, refines them with the prover, then applies the learned algorithm to the tests and proves each result equal to its original.

A program from input/output examples

  
Give a few Input-Output pairs. S2A2 reads structural signals from their shapes, proposes nested predicates top-down (map, filter, fold, per-sublist, templates), prunes candidates that behave the same, and hands a recursive result to fold.pl for a faster version.

The dictionary of algorithms

  
Pure, non-LLM predicates harvested from the author's repositories, plus entries built from them by inventors (map, filter, count, fold, …) and joiners (compose, fork, cond), kept only when their behaviour is new. Prove two programs equal

  
io_proof.pl proves two predicates equal for every input of the declared types. It pairs predicates clause by clause, unfolds non-recursive helpers, compares arithmetic as polynomials, and uses induction on list arguments.

Types from proofs

  
A type is the set of values at an argument slot P/N:I. Variables tie slots together, so sound proof rules give inclusions that hold for every input, classes of related slots, templates, and guards that are implied and can be dropped.
